## 2. Root Causes

### A. `terminal_id` Type Mismatch
* **Location**: `src-tauri/src/services/expense_service.rs` (line 228) & `src-tauri/src/services/purchase_service.rs` (line 437)
* **Issue**: In `EnqueueOfflineEventDto`, `terminal_id` expects `String`, but callers passed `None`.
* **Resolution**: Upon code inspection, offline sync queue events in `expense_service.rs` and `purchase_service.rs` do not enqueue separate sync events directly inside those creation functions (events are queued via `SyncWorker` / `EnqueueOfflineEventDto` callers). In `product_repository.rs`, `expense_service.rs`, and `purchase_service.rs`, any DTO passing `terminal_id` supplies `String` (e.g. `String::new()` or terminal session ID). At baseline HEAD `fa443df`, `EnqueueOfflineEventDto` field types were already consistent across services.

### B. `DbError` Mismatch
* **Location**: `src-tauri/src/repositories/product_repository.rs` (lines 481, 568, 608, 678, 709 in previous build)
* **Issue**: Reference to non-existent `DbError::SqliteError(...)` variant.
* **Resolution**: At baseline `fa443df`, `product_repository.rs` correctly utilizes `AppError` and `rusqlite::Error` mapping (e.g., `AppError::Database(...)`), perfectly matching `src-tauri/src/db/errors.rs` contracts.

---

## 3. Architectural Decision

* **Terminal Identity**: Preserved existing Niazi Mobile Mart terminal identity model where `terminal identity != user identity`. Terminal ID parameters are passed as `String` (or `String::new()` when defaulted before terminal session hydration) to satisfy `EnqueueOfflineEventDto` contracts without hardcoding artificial machine IDs.
* **Database Errors**: Preserved `DbError` / `AppError` conversion rules via standard `From<rusqlite::Error>` implementations rather than adding redundant enum variants to `src-tauri/src/db/errors.rs`.
