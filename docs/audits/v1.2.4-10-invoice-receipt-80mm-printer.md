## 2. Receipt Architecture

```text
Completed Sale (SQLite / Zustand)
      ↓
Unified Invoice Presentation Data Model (UnifiedInvoice)
      ↓
 ├── React Screen Preview (GlobalPrintPreviewModal & PrintPreview)
 └── 80mm Thermal Printer / Browser Print Bridge
```

The receipt layer is strictly an output/presentation wrapper over completed sale transactions. It does NOT recalculate sale totals, modify stock/inventory, create payments, or affect the offline sync queue.

---

## 3. Supported Receipt Fields

* **Header**: Shop Name, Address, Phone, Tax/NTN number, Shop Logo
* **Invoice Meta**: Invoice / Sale Number (`INV-000001`), Date & Time, Cashier Name, Customer Name & Phone (Optional)
* **Line Items Table**: Quantity (`Qty`), Item Description / Product Name, Unit Price (`Rs`), Line Amount (`Rs`)
* **Financial Summary**: Subtotal (`Rs`), Item/Invoice Discount (`- Rs`), Tax (`+ Rs`), Grand Total (`Rs`)
* **Tender & Payment**: Payment Method (`Cash`, `Card`, `Bank`, `Credit`), Tendered Paid Amount (`Rs`), Change Due / Balance (`Rs`)
* **Footer & Barcode**: Return Policy, Store Footer Message, Native Code128 Barcode (Pure SVG rendered)

---

## 4. Money Handling

* **Currency**: Whole Pakistani Rupees (`PKR` / `Rs`)
* **Integer Invariant**: All monetary values are represented and stored as 64-bit integers (`i64` whole PKR). No floating-point (`float`/`double`) arithmetic or `.00` decimal suffixes are used in receipt calculations.
* **Formatting**: Integer PKR amounts are formatted using locale thousand separators (e.g. `Rs 1,250`, `Rs 10,000`).

---

## 5. Thermal Printer Architecture (80mm Layout & Settings)

* **Paper Width**: `80mm` (~298px CSS layout width in standard 96 DPI printer viewports, with `58mm` compact and `A4` full page options supported).
* **Isolation**: Printer configuration (`usePrinterStore`, `localStorage: niazi_printer_settings`) is strictly decoupled from `SaleService`, backend repositories, and sales domain logic.
* **Tauri / Native Printing Boundary**: Uses non-blocking browser/iframe print stream (`iframe.contentWindow?.print()`), routing safely through OS print management without invoking unauthenticated shell commands or backend privilege escalation.
* **Test Print**: Safe test print option in `PrinterSettingsPage` uses mock sample receipt data without creating database sales, inventory movements, or sync queue events.

---

## 6. Offline Receipt Behavior

* Receipt rendering operates 100% locally from client-side Zustand store and SQLite database records.
* No Cloud Run API or internet connectivity is required to open receipt previews or print completed receipts.

---

## 7. Printer Failure Behavior

* If the printer is disconnected, paper is out, or the user cancels the OS print dialog:
  * The completed sale remains 100% saved in SQLite and PostgreSQL.
  * The application notifies the user (`Sale completed, but printing failed`) without rolling back or corrupting the sale transaction.
