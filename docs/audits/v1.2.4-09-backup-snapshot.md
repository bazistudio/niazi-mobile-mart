## 8. Recovery Model

```text
Desktop failure
→ Central PostgreSQL remains authoritative; replacement terminal logs in, pulls sync queue / delta log.

Central database failure
→ Cloud SQL Point-in-Time Recovery (PITR) or automated snapshot restore to a fresh instance.

Application deployment failure
→ Cloud Run versioned revision rollback or Git release commit rollback.

Local SQLite corruption
→ Delete local SQLite file; re-initialize schema and re-pull downstream change log deltas from central server.
```
