# 2. BUSINESS IDENTITY — PERMANENT LOCK

1. **ONE Permanent Organization**:
   - Niazi Mobile Mart is a single physical retail business.
   - Canonical UUID: `00000000-0000-0000-0000-000000000001`
   - Zero SaaS multi-tenancy: No organization signups, no tenant signups, no organization selectors, no dynamic tenant provisioning, no SaaS subscription plans.

2. **Controlled Branch Architecture**:
   - Niazi Mobile Mart may operate multiple branches.
   - All branches belong exclusively to the single Niazi organization (`organization_id REFERENCES organizations(id)`).
   - Default Main Branch UUID: `00000000-0000-0000-0000-000000000002` (`code = 'MAIN'`).
   - Staff users are assigned to permitted branches (`branch_id`).
   - No branch may belong to an external organization.

# 3. CURRENCY & FINANCIAL DATA SPECIFICATION

### PERMANENT NIAZI MONEY MODEL

> **Niazi Mobile Mart stores monetary values as signed 64-bit integer whole Pakistani Rupees. One stored integer represents one PKR rupee. For example, `2000` represents Rs 2,000. The system does not use paisa, minor-unit scaling, or floating-point financial values.**

1. **PKR Single-Currency Lock**:
   - Currency Code: `PKR`
   - Display Symbol: `Rs`
   - Whole Rupee Unit: `1 stored integer = 1 PKR`
   - No minor units: No `paisa`, no decimal subdivisions, no minor unit names.
   - The ERP is single-currency: No USD, EUR, GBP, AED, SAR, multi-currency accounting, or currency switching.

2. **Canonical Storage Mapping**:
   ```text
   Business amount       Stored integer value
   ------------------------------------------
   Rs 0                  0
   Rs 100                100
   Rs 1,500              1500
   Rs 2,000              2000
   Rs 380,000            380000
   ```

3. **Type Mapping Across Layers**:
   ```text
   Layer                 Type
   ------------------------------------------
   Rust Domain / DB      i64 (`Money { rupees: i64 }`)
   SQLite (Local)        INTEGER NOT NULL
   PostgreSQL (Cloud)    BIGINT NOT NULL
   JSON / DTOs           i64 (e.g. 380000)
   ```

4. **Absolute Prohibitions for Financial Values**:
   - **No floating point**: `f32`, `f64`, `REAL`, `FLOAT`, `DOUBLE`, or decimal conversion via float are strictly forbidden.
   - **No currency scaling**: No `* 100` or `/ 100` operations.
   - **No decimal display formatting**: The UI formatting contract is `Rs 2,000`, `Rs 15,500`, `Rs 380,000`. Never `Rs 2,000.00` or `toFixed(2)`.

# 4. IDENTITY & IDENTIFIER POLICY

1. **Canonical Identity**: **UUID v4**
   - Standard 128-bit RFC 4122 UUID v4 format (`xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx`, 36 characters).
   - Generated by Rust native code (local) or online backend (cloud) *prior* to database insertion.
   - Never use auto-increment integers, serials, MongoDB ObjectIds, or client-side random strings.

2. **Database Types**:
   - **Local SQLite**: Stored as `TEXT` with strict check constraint:
     ```sql
     id TEXT PRIMARY KEY CHECK(length(id) = 36)
     ```
   - **Online PostgreSQL**: Stored as native `uuid`:
     ```sql
     id UUID PRIMARY KEY DEFAULT gen_random_uuid()
     ```
   - All foreign keys reference 36-character UUID primary keys with foreign key integrity enforced.

# 5. TIMESTAMP STANDARD

1. **Format**: **ISO 8601 / RFC 3339 UTC** string (`YYYY-MM-DDTHH:MM:SSZ` or with fractional seconds).
2. **Database Storage**:
   - SQLite: `TEXT NOT NULL`
   - PostgreSQL: `TIMESTAMPTZ NOT NULL`
3. **Timezone Policy**: All persistent entities record `created_at` and `updated_at` strictly in UTC. Conversion to Pakistan Standard Time (PKT, UTC+5) occurs exclusively in the presentation/UI layer.

# 6. LOCAL SQLITE DATABASE CONFIGURATION

1. **Database Storage Location**:
   - Development & Production: Located in the operating system application data directory:
     `%APPDATA%/com.bazi.niazimobilemart/data/niazi_local.db` (Windows).
   - Test Isolation: Configurable via `NIAZI_DB_PATH` environment variable or `DatabaseConnection::open_in_memory()`.
   - Never stored inside git repository, executable directories, or temporary caches.

2. **Enterprise Pragmas**:
   ```sql
   PRAGMA foreign_keys = ON;      -- Relational integrity enforcement
   PRAGMA journal_mode = WAL;     -- Concurrent non-blocking reads & writes
   PRAGMA synchronous = NORMAL;   -- Full durability in WAL mode with fast throughput
   PRAGMA busy_timeout = 5000;    -- Graceful lock contention handling (5s)
   PRAGMA temp_store = MEMORY;    -- In-memory temporary tables & sorts
   ```

# 7. TRANSACTION INFRASTRUCTURE

Atomic database operations are handled via `with_transaction`:
```rust
with_transaction(&db, |tx| {
    tx.execute("...", [])?;
    // More atomic operations
    Ok(())
}).await?;
```
- Automatically commits on `Ok(_)`.
- Automatically rolls back on `Err(_)`.
- Used for all multi-table mutations (sales checkout, stock deductions, ledger postings).

# 8. MIGRATION SYSTEM

1. **Tracking Table**:
   ```sql
   CREATE TABLE IF NOT EXISTS schema_migrations (
       version INTEGER PRIMARY KEY,
       name TEXT NOT NULL,
       applied_at TEXT NOT NULL
   );
   ```
2. **Deterministic Execution**:
   - Migrations are sequential and immutable.
   - Each migration runs inside an isolated atomic transaction.
   - Migration runner executes automatically on database connection open.
   - Idempotent: Subsequent runs verify applied versions and execute 0 migrations.

# 9. PUBLIC RATE APP & PLAY STORE USER SEPARATION

1. **Two Distinct Security Domains**:
   - **Internal ERP Users**: Super Admin, Admin, Manager, Cashier, Staff.
   - **Public Rate App Users**: External shop owners and consumers who download the Play Store mobile app.

2. **Strict Data Isolation**:
   - Public users are NOT Niazi employees, branches, or tenants.
   - Public users have role `PUBLIC_USER` and `StaffAccessProfile::public_user_restricted()`.
   - Public users have ZERO access to internal ERP pages or actions:
     - `pos` / `pos:sale` -> DENIED
     - `inventory` / `stock:adjust` -> DENIED
     - `suppliers` / `supplier:ledger` -> DENIED
     - `customers` / `ledger:read` -> DENIED
     - `settings` / `admin:users` -> DENIED

3. **Public Rate Publishing**:
   - Admin in Shop Admin explicitly marks a product as public (`is_public = 1`).
   - The Public API exposes ONLY `PublicRateDto`:
     ```json
     {
       "product_id": "UUID",
       "product_name": "Samsung Galaxy S24 Ultra",
       "category": "Smartphones",
       "selling_rate": 380000,
       "currency": "PKR",
       "updated_at": "2026-01-01T00:00:00Z"
     }
     ```
   - Strict field isolation: NEVER exposes purchase cost, supplier, internal stock counts, margins, or accounting data.

# 11. ONLINE POSTGRESQL SCHEMA BLUEPRINT

The future online PostgreSQL database mirrors the domain model using the same UUID identifiers and integer whole-PKR money model:

```sql
-- Identity & Organization
CREATE TABLE organizations (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(255) NOT NULL,
    currency VARCHAR(3) NOT NULL DEFAULT 'PKR',
    currency_symbol VARCHAR(10) NOT NULL DEFAULT 'Rs',
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE branches (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id UUID NOT NULL REFERENCES organizations(id),
    name VARCHAR(255) NOT NULL,
    code VARCHAR(50) NOT NULL UNIQUE,
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Public App Users (Separate from internal staff)
CREATE TABLE public_users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    phone VARCHAR(30) NOT NULL UNIQUE,
    name VARCHAR(255) NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Public Rates for Play Store App (1 stored integer = 1 PKR rupee)
CREATE TABLE public_rates (
    product_id UUID PRIMARY KEY,
    product_name VARCHAR(255) NOT NULL,
    category VARCHAR(100) NOT NULL,
    selling_rate BIGINT NOT NULL CHECK (selling_rate >= 0),
    currency VARCHAR(3) NOT NULL DEFAULT 'PKR',
    is_public BOOLEAN NOT NULL DEFAULT TRUE,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_public_rates_is_public ON public_rates(is_public);
```

# 12. BACKUP & DISASTER RECOVERY

1. **Online SQLite Backup API**:
   - SQLite WAL mode allows concurrent backup without blocking readers or writers.
   - Backup uses SQLite's native backup API (`VACUUM INTO` or `rusqlite::backup`).
2. **Restoration Protocol**:
   - Database restore replaces `niazi_local.db` while application is closed or in maintenance lock.
   - All migrations verify and reconcile automatically on next launch.
